## Changes and arithmetic

Added nullable immutable started_at/completed_at columns to runs, without
backfilling history. New starts persist server UTC time; terminal transitions
persist completion once, and retries/status polls do not change it. The status
API adds started_at, completed_at, advisory_created_at, officer_decision_at and
officer_decision. Historical completion remains null when not recorded; it is
not inferred from updated_at, decision time or browser time. Current-version
draft/decision hashes and approval authority are unchanged.

A shared formatter requires explicit timestamp offsets and converts to
Africa/Nairobi independent of browser timezone. Missing/invalid/naive values
show `not available`. Source-date formatting remains date-only.

Dashboard keeps React/Vite/API/SQLite architecture. Uses local system fonts,
stronger text contrast, compact branding, a timeline, visible review status,
comparison before detailed trace, prominent net/cost totals, source-date labels,
backend-derived leader, sellable kg, expandable actual tool inputs/outputs,
progress summary and dated inbox rows. Keyboard focus is visible; mobile cards
stack without horizontal overflow.

Actual display defect: the comparison quantity previously fell back to editable
request input while draft loading was incomplete. It now uses immutable draft
quantity/unit or `not available`. Run/draft/events update as one matching
snapshot and old-selection responses are ignored, preventing a previous draft's
quantity from appearing beside a newly selected comparison.

Actual 650 kg baseline: A gross 26000.00, costs 2000.00, net 24000.00 KES;
B gross 29250.00, costs 8000.00, net 21250.00 KES. Backend winner A, advantage
2750.00 KES. Display matches; no backend arithmetic defect or hardcoded winner.
Model, fixture prices/observations, recorded content, approval safeguards and
previous outcomes were not changed.
