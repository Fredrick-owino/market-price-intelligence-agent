## Enforced retrieval boundary

- Both application and wrapped server require exactly `fetch` with the fixed URL,
  `raw=true`, `max_length=12000`, `start_index=0`. Arbitrary model URLs, other tools,
  changed arguments and the robots URL as a tool target are rejected. The client
  accepts no URL CLI argument. Server prompts are hidden and disabled.
- The version-checked upstream server uses a substituted HTTPX AsyncClient in its
  isolated process. Both robots and content requests use the constrained transport.
  Only the exact fixture URL and `https://raw.githubusercontent.com/robots.txt`
  can reach that transport; schemes, userinfo, ports, aliases, encodings, query
  strings and fragments outside those exact strings fail before DNS.
- Every DNS answer must be a globally routable unicast address. Private, loopback,
  link-local, metadata, reserved, shared-address space and IPv6 transition/mapped
  addresses are rejected. A mixed public/private answer set fails entirely.
- The connection uses the checked numeric socket address, with no second hostname
  resolution. TLS uses the original hostname with the system trust store and
  hostname verification. The connected peer is checked against the selected IP.
  This addresses DNS rebinding between validation and connection; initial URL
  validation alone would not. No environment proxy, credentials, cookies or retry.
- All redirects, including robots redirects, are rejected before following them.
  No Location target is connected to. Upstream still requests redirect following,
  but the custom transport rejects any 3xx before HTTPX can follow it.
- HTTP bodies are streamed under a **32 KiB** cap, compressed bodies rejected,
  declared lengths validated, and truncated declared-length bodies rejected.
  Socket operations have **10-second** timeouts; the body-loop deadline is
  **15 seconds**, and the async HTTP wrapper has a **20-second** timeout. The
  MCP request timeout is **45 seconds**, total session deadline **60 seconds**,
  with bounded SDK subprocess teardown in addition to the deadline. Blocking
  resolver/thread work cannot be forcibly cancelled within Python; subprocess
  termination is the outer boundary, not a claim of instant thread cancellation.
- Fixture HTTP status must be 200. Robots 5xx fails closed; upstream's actual
  robots parser and 401/403 denial policy remain active. Other robots 4xx follow
  the inspected upstream policy. No ignore-robots option is used.
- Returned content must have the expected upstream raw envelope, one text block,
  bounded output, exact fixture size, valid JSON, all synthetic labels and exact
  SHA-256. The local fixture is also verified before launch. A truncation marker,
  altered number or injected instruction cannot pass. No retrieved text reaches
  a model prompt, instruction interpreter, executable path or persistence API.

This is a reviewed application HTTP boundary around pinned upstream code, not
an OS network sandbox against a malicious/replaced Python process. Process/SDK
isolation prevents dependency collision; it does not itself enforce egress.
TLS/system DNS/trust-store integrity remain platform assumptions. HTTP header
parsing uses Python's standard-library limits; the 32 KiB cap applies to bodies.
The SDK parses MCP messages before the application's output-size check; it is
not claimed to provide a hostile-subprocess memory limit.
