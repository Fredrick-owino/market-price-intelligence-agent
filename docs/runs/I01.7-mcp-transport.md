## Experiment contract and independent expected values

The resource `synthetic://sokosignal/I01.7` exposes
[`data/synthetic/I01.7-market-comparison.json`](../../data/synthetic/I01.7-market-comparison.json).
It includes UUIDs, `synthetic: true`, `data_status: synthetic`, a visible synthetic
label, invented provenance, explicit units/date/grade/basis/currency, costs,
capacity and default request. Additional synthetic quote variants exist only to
exercise invalid comparability and missing-cost behavior. No observations were
copied from a real market source.

The tool `compare_market_options` accepts two quote IDs and snapshot ID,
quantity/unit, explicit loss fraction, as-of date and experiment policy version.
Prices and explicit scenario costs resolve from that fixed server-owned snapshot;
the caller cannot inject arbitrary prices. All money/quantity inputs and outputs
are decimal strings. Error payloads have code, field and actionable message;
domain rejections use MCP `isError=true` with structured content.

Policy `I01.7-synthetic-v1` supports confirmed kg only, two distinct markets,
matching commodity/variant/known grade/wholesale basis/KES/exact as-of date,
and explicit synthetic capacity. Unsupported units are rejected, not converted
from an unknown sack weight. Missing fees remain null: gross proceeds are
available, but there is no net winner. Decimal precision is 40; money rounds
half-up to two decimals only at output. Ranking compares the displayed cents;
a tie has no unique winner. This is an experiment policy, not a field freshness
or conversion policy.

Baseline: 1000 kg, zero loss, zero handling, zero fees, observation/as-of date
2026-10-10, grade DEMO-1, confirmed synthetic capacity 1000 kg per market.
The baseline expected arithmetic was supplied in the task; the two variations
were hand-derived separately before running the implementation:

## Transport, evidence and bounds

The CLI starts the server using the same worktree interpreter, over real stdio
pipes. No server object or domain function is called directly by the client/test.
The test starts the CLI as a separate process and asserts its received responses.
Server diagnostics go to stderr; protocol stdout is reserved for MCP.

No existing source/logging implementation was present. The client implements a
small experiment subset of the proposed RunEvent fields: UUID run/event IDs,
sequence, UTC timestamps, SDK/server/tool, input/output, latency and explicit
synthetic/redaction/model-null metadata. Only its fixed synthetic cases are
logged. Local server stderr stays in ignored `logs/I01.7-server-<run-id>.log`;
reviewed public JSONL belongs in `evals/results/`. This is application-level
MCP input/output evidence, not a raw wire-byte capture or a durable audit service.

Bounds: ten-second SDK request timeout, 45-second exchange deadline, 60-second
integration subprocess timeout, zero retries, exactly two selected quote IDs,
bounded string arguments, fixed local resource and a 64 KiB application response
check after SDK decoding. That response check is not a pre-decode hostile-stream
memory limit. No network retrieval/model call is implemented. The client verifies
the server returned normally, the transport context closed and the server PID
no longer exists before emitting `shutdown`.
