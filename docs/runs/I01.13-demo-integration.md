## Added behavior

The officer API now stores a bounded synthetic request before starting the
integrated graph in the background. The only variable input is 1–1,000 whole
kg; crop, grade, origin, date, sale basis and two markets are fixed to the
labelled fixture. The run ID is derived from the authenticated officer and
idempotency key under that officer's configured workflow prefix. Retries with
the same body return the same run; a changed body conflicts. Run status exposes
running, failed, pending review and completed states with comparison and
provenance. A stored `RUNNING` request can resume from its checkpoint after
process restart. Failure never becomes a fabricated draft.

React/TypeScript/Vite displays the synthetic label, quantity and fixed inputs,
progress, gross/cost/net market rows, source/provenance, assumptions,
limitations, exact pending draft version/hash and approval/rejection controls.
The bearer token is typed by the officer and held only in page memory. Session
storage holds only the workflow ID so refresh can restore the run after
reauthentication. The built frontend is served by the same loopback FastAPI
process. No CORS or public binding is enabled. The corrected limitations no
longer state that the current model/officer review is absent; the historical
synthetic source and prior traces remain unchanged.
