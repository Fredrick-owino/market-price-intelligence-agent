## Integration and data boundary

Run the existing recovery CLI with `start --integrated`. The graph first calls
the fixed borrowed Fetch tool over actual stdio MCP. This prerequisite is chosen
by application policy, not by the model. The model still dynamically selects
all three own-server tools: search, deterministic comparison, and private save.
No URL, approval or delivery tool is exposed to the model. Legacy `--model-driven`
and model-free experiments remain explicit modes; replay cannot switch modes.

The borrowed client verifies the raw upstream envelope, exact 9,196 bytes,
SHA-256, synthetic flags, upstream identity and HTTP provenance. Its result is a
host-created bundle of the actual downloaded bytes and provenance, stored in a
separate graph checkpoint before model preparation. The source remains the
commit-pinned public fixture from I01.10; no real data is introduced.

The host serializes that verified checkpoint bundle into a temporary directory
accessible to its own-server subprocess. `SOKOSIGNAL_RETRIEVED_SNAPSHOT` selects
this bundle; every search/comparison revalidates it. Missing or corrupt data
fails without consulting the bundled local fixture. The borrowed client retains
its preflight check of the original local fixture against the trusted hash; that
check supplies no quote data to integrated calculations. Tests run the own server
with its local fixture path deliberately absent and still complete the workflow.

Search and comparison retain original synthetic source references and labels,
plus the verified retrieval URL, commit/hash/size, retrieval timestamp, actual
HTTP status/address evidence, borrowed run ID and upstream distribution/source
identity. The own server recomputes the comparison before saving. The immutable
draft content/hash includes provenance; the checkpoint holds the source bytes,
comparison and exact draft. Revision copies evidence but creates a new version
and hash, invalidating previous decisions. The resumed outcome exposes the same
provenance. Historical synthetic dates remain synthetic; retrieval time does not
make these current market observations.

A failed retrieval routes to a durable failure before model metadata, model
requests, own-server search or advisory creation. Content mismatch or an
instruction-like substitution cannot pass the fixed hash. Raw borrowed output
is never a system instruction or executable code. Verified records enter only
structured tool results; unchanged model policies reject invented IDs, totals,
provenance, extra authority arguments and approval claims.

Review remains the existing **simulated** local command, explicitly named
`simulated:officer-001`. It is not authentication or a real officer's approval.
A stored decision must match the current draft ID/version/hash and exact resume
payload. Approval yields internal review only; rejection yields `rejected`.
Neither sends anything. If an untrusted resume consumed the interrupt before
failing at finalize, the review command can now recover only by validating a
stored decision against the checkpoint draft before continuing that node.

## Limits and outstanding requirements

This is one fixed synthetic scenario, not real price corroboration, field
validation or broad model reliability. The Fetch operation is host-mandated;
model selection applies to the three own tools. The structured advisory language
still forbids free prose. Authentication, practitioner scope, real-data rights,
frontend, delivery, independent review and release/gate requirements remain open.
Original-repository visibility and its historical KAMIS rights blocker are unchanged.

The wrapper is an application boundary around pinned trusted Python code, not an
OS network sandbox. DNS/TLS/system trust and local process/files/checkpoints remain
trusted. Provenance is consistency-checked, not signed remote attestation. HTTP
body caps do not cover header parser memory or SDK message allocation. Blocking
resolver/thread cancellation relies on outer subprocess teardown; no claim of
instant cancellation is made. Outbound adversarial controls use mocked tests,
not a hostile external DNS/redirect service.

A checkpointed retrieval is reused on restart; this is explicit recovery of an
already verified immutable snapshot, not fallback after a failed fetch. A crash
before its checkpoint can repeat retrieval. Model preparation may repeat reads
and inference after a crash, while identical draft writes stay idempotent. Domain
writes and graph checkpoints are separate transactions; arbitrary concurrency,
backup/restore and all crash windows remain unproven. Retrieval has its existing
60-second session deadline plus teardown; model preparation has a separate
configurable deadline up to 900 seconds. Limits apply per invocation, not across
all process restarts. Timings include separately measured retrieval and model
requests; wall time until review includes other orchestration overhead.
